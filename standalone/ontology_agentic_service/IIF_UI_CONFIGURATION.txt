IMPORTANT
---------
The preferred installation is to copy the Python files and YAML files into the matching
AgentsRegistry directories. Do not paste an entire YAML document into the System Prompt field.
Do not use a Python filename or module name as the exported object name.

The failure shown in iif_log.txt used this incorrect mapping:
  module: AgentsRegistry.CodedTools.ontology_external_api_tools
  object: ontology_external_api_tools

There is no exported FunctionTool named ontology_external_api_tools. The corrected layout now
uses one file per UI tool, and every module filename, tool name, and exported object name matches.

SYSTEM PROMPT FIELD
-------------------
Enter only the indented text located under system_prompt: | in the relevant YAML file. Do not
include the literal "system_prompt: |" line, tools:, module:, object:, or can_handoff_to:.

For example, the Ontology Alignment Agent System Prompt begins:
  Build a draft mapping plan before any graph mutation...

It must not begin:
  system_prompt: |

INSTALLATION OPTIONS
--------------------
Option A - recommended, exact and repeatable:
  1. Copy AgentsRegistry/CodedTools/*.py to IIF AgentsRegistry/CodedTools/.
  2. Copy AgentsRegistry/MCPTools/*.py to IIF AgentsRegistry/MCPTools/.
  3. Copy AgentsRegistry/Agents/*.yaml to IIF AgentsRegistry/Agents/.
  4. Remove the obsolete grouped modules ontology_rdflib_tools.py,
     ontology_owlready2_tools.py, and ontology_external_api_tools.py if previously installed.
  5. Restart one IIF instance.

Option B - IIF GUI:
  Create each tool separately and use the exact module/object pair above. File, tool, and object
  now have the same name. Every coded-tool file is self-contained.

OPTIONAL TOOLS
--------------
Keep these disabled until their dependencies/configuration are ready:
  ONTOLOGY_EXTERNAL_API_ENABLED=false
  NEO4J_MCP_ENABLED=false

Owlready2 is imported only when owlready2_analyze runs. Install requirements-owlready2.txt before
calling it. Neo4j MCP needs requirements-neo4j-mcp.txt only when enabled.

NON-TOOL ERRORS SEEN IN iif_log.txt
-----------------------------------
1. NameResolutionError for the Azure user-auth host is DNS/network/VPN related, not an agent tool.
2. WinError 10048 on 127.0.0.1:8001 means another IIF process already owns that port. Run only one
   instance or configure a different port.
3. The tool SyntaxError occurred because generated content appeared before a future import. The
   current asset modules no longer use future imports and are safe from that specific wrapper error.
