SLIDE 1
PRESENTER NOTES - DEFINITIONS
- Personas: intended business users, not extra agents or permission grants.
- Named personas: Product leader, Design engineer, Systems engineer, Manufacturing planner, Quality specialist, Steward and approver.
- Retrieve finds relevant evidence; Trace follows recorded links; Compare checks similarities and conflicts.
- Validate checks configured rules; Explain presents grounded findings; Prepare creates reviewable drafts or evidence.
- Agent role: a configured responsibility with task instructions, permitted tools and approval boundaries, not a separate person or service.
- Skills: reusable task capabilities such as retrieve, trace, compare, validate, explain and prepare; these six labels describe capabilities, not six separately registered agents.
- Worker: a background process that executes queued work and retains progress independently of the open browser.
- Services: the ten APIs that own data and business operations used by the UI, agents and workers.
- Four agent groups on this slide are presentation groupings of 16 core agents, not four extra agents.
AGENTS - ONE-LINE PURPOSES
- Ontology Intake: inspects retained source evidence and prepares it for ontology generation and review.
- Engineering Parser: inspects engineering files and runs configured parsing profiles.
- Engineering Schema-Set Agent: handles related schema files and tracks reviewed schema tasks through commit.
- CEIM Mapper: normalizes supported source records into the common engineering interchange contract.
- Ontology Orchestrator: coordinates ontology review tasks through the registered orchestration tool.
- Ontology Structure Review: reviews declared classes, properties and observable structural issues.
- Semantic Bridge Planner: proposes mappings and identifies unresolved alignment checks.
- Graph Analyst: investigates recorded relationships, where-used, change dependencies and similar-part evidence.
- Business Context Analyst: saves and retrieves business context and recorded where-used relationships.
- OSLC Link Agent: queries linked engineering resources and synchronizes approved remote information.
- Ontology Governor: prepares lifecycle changes, merges and mappings and publishes only through authorized workflows.
- Ontology Steward: evaluates mapping and merge proposals against policy and available reasoning evidence.
- Data Product Governor: prepares, publishes or revokes retained data-product packages through governed operations.
- Data Quality Monitor: inspects pipeline telemetry and invokes registered transformation and processing checks.
- Ontology Inference Advisor: previews available inference and inspects reasoning evidence without granting approval.
- Ontology Export: produces an ontology export through the registered export operation.
WORKERS - ONE-LINE PURPOSES
- Data pipeline worker: executes approved data jobs, including configured distributed processing, using durable job leases.
- Agent workflow worker: executes saved multi-step agent workflows and supports controlled recovery after interruption.
- Data product outbox worker: retries delivery of retained product registrations to the catalog.
STANDARDS - ONE-LINE BUSINESS MEANINGS
- PCA IDO 4.2: the embedded public industrial reference snapshot linked to ISO 23726-1; this is not an ISO certification claim.
- Application ontology: the Nexus-owned vocabulary separating physical parts, designs, documents, requirements and activities.
- AP242: product definitions, model-based engineering information and PMI under ISO 10303-242.
- AP239 / PLCS: product lifecycle support information under ISO 10303-239.
- AP243 / MoSSEC: collaboration and traceability context for modelling and simulation under ISO 10303-243, not a simulation solver.
- QIF: manufacturing quality and measurement information under ISO 23952.
- B2MML / ISA-95: manufacturing operations information connecting business planning and production activities.
- BatchML / ISA-88: recipe, batch information and batch production record structures.
- JEP30 / JEDEC: electronic part model schema information for exchanging component data.
SUPPORT BOUNDARIES
- AP243 has a registered schema profile and retained MoSSEC domain model; this does not establish a complete simulation execution workflow.
- B2MML has a registered schema profile; the schema conversion configuration also includes BatchML recipe and batch record structures.
- JEP30 uses generic schema-set ingestion; no dedicated JEP30 CEIM publication mapping pack was found in this review.
- AP239, B2MML and BatchML schema/parser support is not proof of a dedicated CEIM instance-publication mapping pack.
- Registered roles still depend on configured services, source evidence, permissions and model availability where applicable.
- A score or agent recommendation does not approve interchangeability, engineering change or publication.

SLIDE 3
IIF is the user-requested name for the agentic AI layer. It is not a claim that a new IIF service has been installed or that the separate AOI wrapper owns orchestration. NEXUS currently has ten API services and three workers. The named roles are configured responsibilities in the existing agent catalog, not separate processes. Governor prepares and coordinates proposed changes; Steward assesses retained evidence; authorized workflows control publication. The model provider is optional and must be configured for model-dependent work.
Short-term conversation/context and reviewed long-term lesson records are retained in PostgreSQL through the existing registry. Business-entity relationships and evidence are retrieved from the graph store. Retrieval is scoped and advisory; memory never grants approval or becomes verified source evidence automatically. Retained files preserve original source artifacts; this diagram does not assert that all bytes are stored in the graph database.
The diagram adapts the user-provided service/ontology/data layer reference with an explicit IIF layer and worker row. Arrows are schematic interfaces, not a complete network topology. No automatic source equivalence or complete manufacturing/simulation coverage is claimed.

SLIDE 4
Arrows describe evidence flow, not synchronous calls between every box. Source records enter via supported files or configured remote providers. Remote OSLC operations are read/discover/query/pull-stage; staging does not publish or push remote changes. Pipeline jobs use durable leases; Apache Spark is an optional configured execution runtime and not an extra microservice. Approved publication is a separate governed step. Data can then be retrieved by IIF, Companion and reporting functions. Read-only discovery remains available before publication; this diagram describes the governed consumption path.
PostgreSQL owns operational state, approvals, conversation/lesson records and analytics. Graph projections retain engineering relationships and provenance. Original files remain in retained artifact storage. Workers do not rewrite embedded reference ontologies.
