Agentic orchestration update — 2026-10-06

Implemented paths

1. Workflow recovery retains execution inputs, definition fingerprints, completed
   traces and a pending-step intent written before tool dispatch. Recovery skips
   completed steps, preserves original ownership and the original deadline, and
   records recovery history. Compare-and-swap updates fence superseded executors.
   Original tool definitions and approval requirements must still match.
2. Uncertain mutations block replay. A supervisor records verified downstream
   evidence and either a completed result or a verified not_applied outcome.
   These are audited supervisor attestations, not automatic receipt verification.
   A stale running mutation also requires explicit confirmation that its original
   executor has stopped. Recently active executions cannot be recovered.
3. The ontology-review-and-bridge-plan catalog workflow now has three separately
   checkpointed steps: intake, review, and bridge planning. SHA-256 artifact
   bindings reject source changes between steps. Standalone endpoints retain their
   single-operation behavior.
4. All workflow inputs are preflighted before any tool executes, and resolved
   inputs are checked again before dispatch. The supported DEPO OpenAPI 3 subset
   covers local references, required fields, types, unions, nullable values,
   enums, constants, lengths, ranges, patterns and common formats. Future-step
   references are rejected. Unsupported constraints/formats are rejected rather
   than treated as verified. Semantic business rules still run at service boundaries.
5. Configured stdio MCP servers support initialization, tool discovery and tool
   calls with bounded responses/deadlines and process cleanup. Only operator
   catalogued commands, tool names and agent allowlists are usable. Native input
   schemas are checked, including local definitions. Environment forwarding is
   limited to the configured list and basic process variables. Mutating tools
   still require an explicit downstream approval contract; no MCP write bypass
   was added. Install the configured server in the deployment Python environment.
6. Agent system prompts are used by a new model-backed suggestion endpoint.
   Suggestions must select an allowlisted tool and pass input preflight. They
   remain proposals; they do not execute or grant approval.
7. Companion SSE sends retrieval status immediately and streams Ollama NDJSON
   content as it arrives. The final evidence-bearing response is authoritative,
   replacing provisional text if model generation fails. Disconnects cancel the
   stream worker. NDJSON frames and complete responses are bounded.
8. Mapping candidates now include explicit datatype, domain/range, duplicate,
   class/type and supplied ontology-scope checks over RDF evidence. Conflicts are
   marked invalid; absent metadata and complex reasoning remain unresolved.
   Publication always requires the existing human approval path.
9. Anonymous workflow status requests are authorized before querying storage.

API additions

POST /api/v1/workflow-runs/{run_id}/recover
  Body: approved_by and a current approval_token (token authentication).
  Use graph read access in the header for read workflows. Governed workflows
  independently verify the supervisor approval before each dispatched step.

POST /api/v1/workflow-runs/{run_id}/reconcile
  Body: approved_by, approval_token, outcome (completed or not_applied), evidence.
  completed also requires the actual downstream result object. For a stale
  running mutation, executor_stopped must be true after external verification.

GET /api/v1/mcp-servers/{server_id}/tools?cursor=...
  Read access required. Returns native tool metadata and pagination cursor.
  To enable a reviewed tool, add a transport=mcp catalog tool with server_id,
  native name, mutates classification and an agent tool allowlist entry.

POST /api/v1/agents/{agent_id}/suggest
  Read access required. Body: task. Returns a proposal command and approval status.

Admin now offers recovery for eligible runs and receipt/evidence entry for
uncertain writes. Recovery cannot extend an expired deadline. Older runs lacking
retained execution inputs and definition fingerprints cannot be recovered.

Deployment

Use depo-services-audit-fix.zip and depo-services-fix-deployment.txt. Restart the
agentic service and reload the rebuilt frontend. New state fields use the existing
PostgreSQL JSON registry; no schema migration or new Python dependency is needed.
Each selected HTTP service must expose its live /openapi.json route through its
configured endpoint for preflight. Keep the current root .env.local and runtime.
