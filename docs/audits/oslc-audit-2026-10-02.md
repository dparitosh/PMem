# OSLC audit — 2026-10-02

Scope: standalone service on port 8015, graph-backed server routes, lifecycle access, remote client/snapshot synchronization, query parsing and TRS. Source review and dependency-free reproductions; not an OSLC standards certification or live database/gateway test.

## Confirmed findings

1. **P1 — Unauthenticated graph and snapshot reads.** `backend/routes/oslc_routes.py` query/resources/TRS/dictionary/taxonomy handlers have no identity dependency. `backend/oslc_service/router.py:21,28,46,51` remote reads and staged snapshot reads are also unprotected. The service factory adds CORS/correlation but no blanket authentication. Lifecycle resources separately enforce identity/grants; that does not protect these other routers. Add read authentication at data-route boundaries, retain intentionally public discovery/health if desired, and apply resource/snapshot scope policies.
2. **P1 — Approval credential forwarded and persisted.** `router.py:36-39` validates parameters containing approval_token and approved_by, then passes the same object into `sync.py:77-78`. The remote client serializes it into URL query parameters and `sync.py:41` saves it in snapshot metadata. Unauthenticated snapshot reads make the leak more serious. Strip approval/auth fields before network dispatch and persistence, allowlist query parameters, and redact previously stored snapshots. Reproduced with a synthetic test credential; no customer secrets used.
3. **P1 — TRS Base resurrects deleted resources.** `oslc_trs_service.py:325-335` skips Deletion events but continues adding older Creation/Modification events for the same URI. Determine each URI's latest event before constructing membership; a latest deletion must suppress its earlier events. Reconcile events with current resource existence.
4. **P1 — TRS Base truncation cannot be fully consumed.** `oslc_trs_service.py:262-353` caps the Base at 1000 and returns truncated without continuation. A consumer rebasing cannot enumerate all resources, despite receiving cutoff_order. Introduce stable complete Base paging and a consistent cutoff/snapshot boundary; do not represent a partial Base as a completed rebase.
5. **P2 — Remote sync silently stages zero resources from DEPO itself.** `sync.py:34` recognizes value/resources/results, but the local query service returns members (`oslc_service.py:1174`). Reproduced with one member yielding resource_count=0. Handle members explicitly, reject malformed structures, and preserve/follow bounded paging rather than reporting a complete snapshot from just one page.
6. **P2 — Query parsing mishandles quoted values.** `oslc_query_service.py:169-176` searches operators inside quoted strings: title="a>=b" is rejected. `_parse_value` strips quotes before numeric conversion, so id="001" becomes integer 1. Both reproduced. Scan operators outside quotes and preserve quoted string types with explicit escape handling.
7. **P2 — Remote disable switch is not enforced.** `oslc_service/router.py` remote handlers and client dispatch do not check OSLC_REMOTE_ENABLED. A configured remote URL can still be used with the feature disabled, unlike the agent remote OSLC route. Enforce the switch at dispatch and return accurate enabled/configured health state.
8. **P2 — Remote response memory and structure are unbounded.** `client.py:30-34` buffers a whole response and assumes JSON object output; remote catalog does not catch JSON decode failures. Add streamed decoded-byte limits and strict object/list contracts. Validate URL ports with the shared URL validator. Existing HTTPX redirect rejection should be retained.
9. **P2 — Synchronous graph/TRS operations run inside async handlers.** `backend/routes/oslc_routes.py` calls synchronous Neo4j and registry/file operations directly from async functions. This can stall all service requests. Use synchronous FastAPI handlers or awaited offload with bounded database operations; readiness currently checks only PostgreSQL although graph routes also require Neo4j.
10. **P2 — Lifecycle content negotiation rejects ordinary Accept lists.** `lifecycle.py:69-85` matches the entire header against one media type. Lists, quality weights and charset parameters produce 406 even with a supported representation. Parse supported media ranges/quality values and choose an acceptable format; do not use substring matching.

## Checks and limits

Three direct reproductions confirmed quoted-operator rejection, quoted numeric coercion and zero-member snapshot staging. A fourth confirmed persistence of a synthetic approval token. Query construction parameterizes values and sanitizes property names; remote resource types reject traversal; remote transport disables redirects and environment proxy trust; lifecycle reads use grants, private caching and ETags; TRS writes use advisory locks in PostgreSQL mode. These checks do not establish live API/gateway behavior. Existing dependency-heavy OSLC tests were not run because test dependencies were removed. No application code changed in this audit.


## Fix implementation

All ten findings have code changes: protected data routes and explicit snapshot grants; approval parameter allowlisting and legacy redaction; latest-event deletion filtering; retained Base snapshots with complete paging, capacity failure and expiry cleanup; members parsing with explicit partial snapshots; quoted-value parsing; enforced remote feature switch; streamed remote byte limits/object validation and shared URL validation; synchronous graph handlers and Neo4j readiness; weighted media negotiation. Local query responses now include filter-preserving nextPage links. No automatic graph publication or unapproved remote pagination was added.

Focused tests cover quoted values, content negotiation, secret removal, malformed collections, partial status, deletion suppression, stable paging and protected route declarations. Full dependency-heavy FastAPI/Neo4j/PostgreSQL tests remain pending; dependencies were not installed for this run. TRS consistency across independently committed graph mutations and event writes still needs end-to-end validation. This fix does not claim standards certification. Commit and push status is recorded in Git.
